# /loop 用プロンプト — v7（フルP・査読耐性・自己ペース動的モード）

起動例:
`/loop このファイル(outputs/stockleague_edition/V7_LOOP_PROMPT.md)の指示に従い、STOCKリーグ提出版v7の改善ループを1イテレーション実行する`

---

## 使命

STOCKリーグ提出版 **v7** を、**ファイナンス論の世界的権威の研究者が通読して全てを理解でき、この研究の規律の完全性に感嘆し、実際に現実の研究者にそのまま見せられる水準**まで反復改善する。同時に、**ゼミの初学者が読んでも主張と結論を迷わず追える**こと。v7 は前版と異なり、**提出ポートフォリオ自体を「守=真バフェット」に組み替える(フルP)**。

**正典**: `outputs/stockleague_edition/V7_PLAN.md`（あるべき姿・PF構成の決定と理由・チーム指摘応答§3・WP・14軸ルーブリック・ハードゲートG1〜G12・Figma仕様§6・圧縮表§7）。
補助正典: `work/pure_buffett_benchmark/FINDINGS.md`（真バフェット/多期間/ハイブリッドの数値と誠実性の防衛線）、`FIGMA_REBUILD_SPEC.md`（→v7更新）、`EXPERT_AUDIT_v4.md`。矛盾時は V7_PLAN.md が優先。

## 絶対規律（違反はいかなる進捗・スコアでも FAIL）

1. **LOCKED不可侵**（v4/v5/v6の全ファイル）。生成・更新は **v7系ファイルのみ**（出力名にv7。上書き事故に注意）。
2. **数値手打ち禁止**。本文・図表・補遺の全数値はスクリプト出力(JSON/CSV)からの自動転記。
3. **実装・正典データを読んでから書く**（記述はコード挙動と1対1対応）。
4. **"超える"をチューニングで作らない**。PFは §2.3 の事前規則で機械選定し、出た数字をそのまま報告。負の結果も開示。
5. **in-sample 枠の必須併記**。"超える"の主張の近傍に必ず「これは2026-06選定を過去に当てた自己検証であり、将来の市場超過の証明ではない」を置く。
6. **人間パート**（取材・学んだこと・SDGs理由・表紙記入・チーム名）は記入欄のまま。創作は blocking 違反。
7. 本編 ≤30頁・全文字10pt以上。あふれる詳細は技術補遺へ。

## このイテレーションの手順

1. **`V7_PROGRESS.md` を読む**（無ければ V7_PLAN.md §4 の WP0〜9 と §9 成果物からテンプレを作成）。未完了項目を依存順(W0→…→W9)に1〜3個選ぶ。
2. **選んだ項目を V7_PLAN.md の受入基準まで実施**する。特に:
   - **W1(PF確定)を最優先で通す**: §2.3 の事前規則で20社(5/5/5/3/2・守=真バフェット5)を確定し `portfolio_v7.json` を生成、多期間で "超える"(§1.1 の4条件) を再検証。**成立しなければ重み方式の範囲で対応し、それでも不足なら主張を正直にスコープする（勝たせる調整はしない）**。
   - 図版(W6)は **Figma でピクセル単位**に作成/修正し、V7_PLAN.md §6 と `FIGMA_REBUILD_SPEC`(→_v7) の全指摘（特に図表Ⅱ-3の矢印起点・日本語ラベル、Ⅱ-4の表題と日本語説明）を反映。**画像内テキストは pdftotext の死角なので必ず目視監査**。
3. **ビルド**（本編＝パス1→soffice変換→make_tocmap→パス2→soffice変換／補遺も同様）し、**ハードゲート G1〜G12 の機械チェック**を実行。FAIL は先へ進む前に即修正。
4. **W1〜W8 が実質完了したら毎イテレーション、二重ペルソナ査読を行う**（下記「査読プロトコル」）。指摘を全件 `V7_REVIEW_FINDINGS.md` に記録（イテレーション番号・箇所・分類 blocking/major/minor・タグ）。blocking/major は即修正、minor も原則当該ループ内で修正。続けて **14軸ルーブリック(V7_PLAN.md §5)** で採点し、軸ごとの根拠1行つきで `V7_SCORECARD_ITER.md` に追記。**チーム指摘§3マトリクスの全項の処置状況**も毎回更新。
5. **収束判定**（V7_PLAN.md §8）: G1〜G12 全PASS ＋ 14軸すべて≥9.0 ＋ 二重ペルソナ査読が **2イテレーション連続** で
   - 権威ペルソナ: blocking=0・major=0・minor≤2、例示的長所3つ以上、「実在の研究者にこのまま見せてよい／この研究に感嘆する」= YES
   - 初学者ペルソナ: 「主張(何を買い、なぜ超えると言えるか)と結論(超えたのか)を迷わず要約できる」= YES ／ 難語0
   を満たしたら **確定手順**（SCORECARD_v7.md → VERSIONS.md 追記 → 本編・補遺・Figma版の LOCKED → referee_briefing_v7.md 最終化）を実行し、`ScheduleWakeup` を `stop: true` で呼んでループを終了する。
6. 未収束なら `V7_PROGRESS.md` を更新（完了・残・頁収支・次の先頭項目・既決指摘・チーム指摘進捗）し、**1200秒後**の wakeup を予約して終了。同一項目が3イテレーション連続で未達なら代替アプローチを台帳に記録して切替。30イテレーション超過で中間報告を台帳に書き、**基準を緩めずに人間の判断を仰ぐ**。

## 査読プロトコル（二重ペルソナ・毎回）

### 主ペルソナ（必須）— ファイナンス論の世界的権威
実証資産価格理論（ファクター投資の原典群を書いた側）とバックテスト方法論（**過学習・データスヌーピング・多重検定・look-ahead/生存者バイアス**の第一人者）の双方に通じ、日本株の制度実務(EDINET・単元・TOPIX構成・東証PBR改革)も知る研究者。学生の野心には好意的だが、**数値の出所・定義の曖昧さ・主張の較正・因子帰属には一切妥協しない**。
- **読む順**: 要旨→"超える"の定義(Ⅰ冒頭)→結論/山場(超えたのか)→Ⅰ章(投資テーマ)→Ⅱ章(式を1本ずつ検算する読み方)→Ⅲ章(検証・多期間・真バフェット対照)→補遺§A〜H＋新3節→通読で文章のつっかかりを拾う。
- **特に容赦なく検める点**: (a) "超える"が in-sample の後付けでないか（守5=真バフェット差替が事後の答え合わせに見えないか、事前規則で機械選定か）。(b) 「超えた」の主張がリスク・因子(価値/品質/低ベータ/サイズ)への曝露で説明できてしまわないか＝アルファか因子か。(c) 多重検定(16通り検査等)の補正。(d) 再現可能性(データ・シード・定義)。(e) 経済的直観の有無（統計だけでない）。(f) 不利事実の等格開示。**(g) AI/半導体テーマ集中(現状=重み40%・電気機器7社・業種HHI0.16・β1.22)の妥当性——「生まれる堀=意図的テーマ賭け」として開示され設計意図で正当化できるか。過大(blocking/major)と判断するなら、事前規則の範囲で離の役割予算(28%)低減 or 離4社化により緩和し、"超える"(全条件)が維持されることを build_portfolio_v7.py 系で再検証してから反映する（ユーザーが本判断を査読に委任済み・V7_PROGRESS.md 項目4）。**
- **義務**: 「少しでも引っかかる点」を遠慮なく全件記録。同一指摘の再出は「既決」参照で重複させない。毎回、例示的長所と「実在の研究者に見せてよいか／感嘆するか」の YES/NO を明記。

### 補助ペルソナ（必須）— ゼミの初学者読者（チームメンバー相当）
金融の専門教育を受けていない大学生。30頁を通しで読む。
- **検める点**: (i) 軸が2つ(3つの堀と守破離)で迷子にならないか＝単一軸で読めるか。(ii) 「何を買い」「なぜ超えると言えるのか」「結局超えたのか」が明快か。(iii) 難語(候補宇宙・閾値・分位等)や言い訳がましい山場が残っていないか。(iv) 図表が自立して読めるか（特に図表Ⅱ-3の矢印、Ⅱ-4のA項目説明）。
- **義務**: 迷子になった箇所・戻って読み直した箇所を全件記録。「主張と結論を迷わず要約できるか」の YES/NO を明記。

## 停止・保留
- 保留: 人間にしか決められない事項(実取材・チーム名・SDGs理由・学んだこと)はゲート除外・空欄維持。
- 未決の設計判断（本命の重み方式＝役割予算/最小分散/均等）が W1 再検証後も割れる場合は、判断根拠を台帳に記し既定=役割予算で進めつつ、中間報告で人間確認を仰ぐ。
- 絶対規律違反・"超える"のチューニング疑い・LOCKED誤操作を検知したら即停止して台帳に記録。
